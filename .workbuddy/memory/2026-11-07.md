# 2026-11-07 工作日志

- 面试问答：FastDFS 架构与副本机制（按 3 机集群口径：3×(tracker+storage)，group1 三副本）。
  - 核心结论：FastDFS 单写+异步复制，**写成功 1 个副本即算成功，无 quorum**；副本数=组内 storage 数（无副本参数）；写节点挂→本次失败重试重分配（心跳 30s/check_active_interval 120s），副本节点挂→恢复后追 binlog，WAIT_SYNC→SYNCING→ONLINE→ACTIVE 后才接新写。
  - 分片口径澄清：分片 10MB，100MiB 是测试文件总大小（简历数字别被面试官带偏）。
  - 已核实参数：`storage_sync_file_max_delay`（tracker.conf，默认 86400s，同步延迟容忍度，超了可能追不齐增量需重新入组全量同步）。
- 产出文件：`面试梳理_FastDFS与副本机制.md`（项目根目录，与 `面试梳理_分片断点续传.md` 配套）。
- 拓扑演进：3 机对称版 → **5 机生产版（用户选定口径）**：2 专用 tracker（对等，storage 向所有 tracker 上报，client/mod_fastdfs 配双地址故障转移）+ group1 两 storage（**2 副本**）+ 1 台 nginx+fastdfs-nginx-module（HTTP 入口，proxy 兜底同步延迟 404）。已指出商榷点：单 nginx 单点（keepalived）、2 副本挂一台即零冗余（预算允许上 3 副本/冷备）、业务层机器归属。
